Technical Approach

How should we build this blog? Each approach prioritizes different things.

A

Pure Static HTML + CSS (Recommended)

Hand-crafted HTML pages with vanilla CSS. No build tools, no frameworks, no dependencies. Deploy directly to GitHub Pages.

Pros

  • Zero dependencies — nothing to install or update
  • Loads instantly — no JS overhead
  • Easy to understand and edit
  • Perfect GitHub Pages deployment
  • Will work unchanged for decades

Cons

  • Adding blog posts means creating HTML files manually
  • No templating — shared elements (nav, footer) duplicated across pages
  • Tag filtering needs a small JS script
B

Static Site Generator (Hugo / Jekyll)

Use a generator like Hugo or Jekyll. Write content in Markdown, templates handle layout. Built-in blog/tagging support.

Pros

  • Markdown for blog posts — easier to write
  • Templating eliminates duplication
  • Built-in tags, categories, pagination
  • Jekyll is natively supported by GitHub Pages

Cons

  • Requires learning the generator's conventions
  • Build step needed (or rely on GitHub Actions)
  • Theme customization can be frustrating
  • Dependency on tool updates
C

Lightweight JS Framework (Astro / 11ty)

Modern static-site tools that output pure HTML. Component-based development with zero client-side JS by default.

Pros

  • Best developer experience
  • Component reuse without duplication
  • Markdown support + powerful templating
  • Ships zero JS to the browser

Cons

  • Requires Node.js and npm
  • Build step required
  • More complex project structure
  • Overkill for a personal blog with ~6 pages
